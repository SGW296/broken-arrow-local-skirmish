# Build and validate the offline lobby

Use your own Broken Arrow v1.2.0 installation and its existing MelonLoader 0.7.3 setup. This project does not distribute game assemblies or configure a loader/launcher. The root installer installs a release package only; it does not download MelonLoader.

## Local build

Requirements: Windows x64, .NET 6 SDK, and a working offline modded game launched at least once so MelonLoader generated the local interop assemblies.

```powershell
dotnet build -c Release src/BALocalSkirmish.csproj -p:GameDir="D:/Games/Broken Arrow"
```

Output: `src/bin/Release/BALocalSkirmish.dll`. The project references the local loader and generated assemblies without copying them to the output. Missing dependencies must be generated by the user's own game installation, not committed or downloaded from this repository.

## Checks

```powershell
# Managed fixtures only; no game installation required.
./scripts/Verify-Lobby.ps1 -ManagedOnly

# Release validation: build, managed fixtures, Harmony registration and local IO fixtures.
./scripts/Verify-Lobby.ps1 -GameDir "D:/Games/Broken Arrow" -ReportPath artifacts/validation.json
```

The release runner records observed assertion totals and the built DLL hash. Fixtures exercise production selection, persistence, slot policy, asset ownership and lifecycle with managed stand-ins. The Harmony fixture exercises managed dispatch and compiled registration. Neither runs Unity/IL2CPP; in-game acceptance is recorded separately in `docs/ALPHA-VALIDATION.md`.

Public CI runs the managed and temporary-file fixtures only. It cannot compile the full mod or run native registration without proprietary local dependencies.

## Package a release

```powershell
./scripts/Package-UI.ps1 -OutputDir artifacts/Local-Skirmish-Lobby-3.1.0-alpha.1 -ValidationReport artifacts/validation.json
```

Use a fresh output directory. Packaging includes the built mod, licence, install/diagnostic tools and public documentation. The manifest records the version, source commit, hashes and reported validation. A report for a different DLL/version must fail. Packaging without a validation report must not imply validation passed.

Build/package from a committed source state for a public release. Verify both directory and ZIP contents against the manifest. Do not include local logs, saved setups, generated game DLLs, extracted assets or AI investigation files. Keep experimental AI behavior in its separate project/branch.

The old upstream `dist/BALocalSkirmish.dll` is absent from this release branch. Earlier upstream commits remain available in Git history.
